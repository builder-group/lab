# MidiMarble UX

MidiMarble is a marble track builder whose tracks play music. A run looks satisfying in short-form video because its visual rhythm follows the musical rhythm. The app owns music and track building. Blender owns the look and the final render.

The product serves two kinds of people with one project:

- A beginner composes a track in the app, styles it through presets and agents and renders without opening Blender
- An advanced user opens the same scene in Blender at any time and changes anything the app does not own

The app is fully offline. It uses tools installed on the computer: Blender is required, and an agent is the person's own Claude Code, Codex or Claude app, connected through a local MCP server. There is no account or cloud storage.

## Flow

1. **Start** from a song (a MIDI file or a recording) or an empty project
2. **Compose** the marbles' tracks and the run on a flat wall
3. **Film**: choose the look, camera and titles with themes, skins and Decor, or open Blender for detailed work
4. **Export** the film; Blender renders it in the background

## Window

A window holds one project; there are no document tabs until several projects can really be open at once. The title bar shows the project title with its edited state, Home to return to the start window, the panel toggles and the Agent button.

The start window offers New Project, Import Song… (one panel for a MIDI file or a recording, starting a project named after the file) and Open Project…, and lists recent projects and the examples in two groups, each a gallery of 9:16 stills about 100 px wide in three columns with the name under it and the detail as its tooltip, like GarageBand's project templates. Songs show the music import end to end: Jingle Bells, two marbles built from a MIDI file, and Tap Along, one marble on hits suggested from a recording. Techniques each isolate one behavior: Staircase, Zigzag, Long Gap, Windmill, Two Marbles and Brass Sections. An example opens as an unsaved document named after it, like an untitled macOS document, so Recent does not fill with copies; its song file is copied into the package like an imported one, so the Song layer and its inspector show it. See Onboarding. Pieces are named per type in time order, marble after marble (Platform 1, 2, 3 down the first marble, Rail 1, 2 in the order they play), and a new piece continues after the highest number in use.

The inspector edits the selection and lets relations navigate. A linked piece's link panel (Plays or Follows) selects the note it plays (or the marble it follows) and its Detach button detaches it in place; a piece tied to nothing has no link panel, and **Play a Note…** (arms it for a click on a note's dot; any other click or Escape stops) and **Follow a Marble…** are in its context menu and ⌘K. The **Shape** panel sets the piece's size (Length, Thickness, Depth, Arms, Run Height…), which skins follow; all but Depth is what a marble touches, its hitbox. The collapsed **Physics** panel holds how the piece behaves (Bounce, Brake, Spin); a hit's inspector edits the note's pitch, velocity and time, plays the new pitch, and its Played By row selects the platform again, or Add Platform places an auto-placed one on the open dot. Timing is a status pill in the header (On Time, 12 ms Late, Missed, Stopped, Blocked, Open, as in words.md) with the detail in its tooltip. Without a selection the inspector shows the Scene. The title bar holds the project's actions in both workspaces: the Blender button, whose menu opens the scene in Blender, restarts it or shows its log, Agent and Export Film….

The desktop app has a macOS menu bar with the app's commands (File, Edit, View, Window, Help), built from the same command registry as ⌘K, so every command is discoverable with its key; the layout is in design-language.md, Commands. File has New Project…, Open Project…, Open Recent with Clear Menu, Close Project, Save, Save As…, Import Song… and Export Film…. Save As… (⇧⌘S) of a saved project copies the package with every file to the chosen place and keeps working on the copy, as in macOS; for an unsaved example it is Save. The save panel is titled New Project for File > New and "Save Jingle Bells" when an unsaved project is saved.

The default frame is 9:16. It can be changed, but Compose warnings use the chosen frame from the start. The app targets macOS. Project length has no fixed limit; the user decides where the run ends, like the end of a video timeline.

**Ways back and familiar edits.** File's Revert to Opened… asks first, returns the project to how it opened as one more Undo step, and the first save after opening keeps the file it overwrites as `project.json1` in the package, like Blender's `.blend1`, to restore by hand. Undo and Redo name the step ("Undo Move Platform", "Undo Tilt"). ⌘C and ⌘V copy pieces in Track, titles and Decor in Film, also into another project: a tied piece pastes as a free piece, clear of the run like Duplicate. F2, or Return on a selected row, renames. Every marble, the Wall and each title has an eye in Layers, a light none, as the Draft draws no light and Blender's frames hold them all: a hidden layer leaves the views, for this session only, and never the film. A marble's eye hides its pieces too and dims their rows, like Blender's Outliner, and showing it again leaves a piece hidden by its own eye hidden; while one is hidden Film's preview is the Draft, since Blender's frames hold every layer. Only Decor's eye is saved and also leaves the film. Right-click works in Film's preview and on 3D's empty space, with what works there; the Insert menu mirrors +, and the agent items live in the Agent button and ⌘K.

## Onboarding

The same window serves a beginner and a power user; there is no Beginner mode. Help is optional and never blocks the window.

- **New projects and examples open unsaved.** New Project opens straight away; the first Save asks where to keep it. The host keeps an opened example in a temporary location: a folder in the app's cache (`Unsaved Projects`) on macOS, a separate key range in the browser's storage. It autosaves there, so a reload or relaunch reopens it, and it is never listed in Recent. Opening another example clears the earlier unsaved one. The title shows the example's name and, once it has changes, "Not Saved". Save (⌘S) asks where to save it with the save panel and moves the package there with its song and every other file; the project then continues as a normal autosaved project in Recent, named after the chosen file. Closing it with changes (Home, Close Project, New Project, Open Project…) asks "Save changes to Jingle Bells?" with Save…, Don't Save (⌘D) and Cancel; an unchanged example closes silently. Undoing every edit makes it unchanged again; after a reload the autosaved revision counts as a change. Quitting the desktop app does not ask yet, because the unsaved example reopens at the next launch
- **Quick Help** (Help › MidiMarble Help, ⇧⌘/ or Quick Help in ⌘K) labels the window's regions in place with one line each: Compose and Film, Layers, Tools, Wall (Preview in Film), Inspector, Timeline, Song, Note Summary, Transport, Blender, Agent, Export Film…. While it is on, a panel at the bottom right of the wall explains the control under the pointer with that control's own tooltip and shortcut; elsewhere in a region it repeats the region's line. The window stays fully usable. Escape, the shortcut or the panel's × end it; it is always off at launch
- **Empty project**: with no song and no hits, the bottom of the wall shows **No Song Yet** with one line of help and Import Song… as the first step, and Add Marble when no marble is left, like GarageBand's empty project. Hits don't need a Song: T adds one at the playhead while stopped and taps along while playing.
- **First-run hints**: at most three one-line hints, each shown once, where the next step is. "This is your song: each marble plays some of its notes" beside the Song layer's row when a project with a song opens; it goes once the song plays or the project is edited. "Press N for the next platform, or ⇧N to build the whole track" beside the earliest open dot once the song hint is gone (or at once without a song), while no piece is on the wall; it goes when a platform fills a note. With a song and no hits yet, "Press T and tap along: each press adds a hit to this marble" beside the empty marble track comes first; it goes once a marble has a hit or a song. "Switch to Film to choose the look and export" under the Film tab once an edit leaves every hit on time; it goes when Film opens. Each has a × that dismisses it. A hint counts as seen once it is on screen, which is remembered across launches; Reset Hints in the command palette shows them again. Hints wait while Quick Help is on

## Compose

Compose is the app's editor. It has full direct control and a deliberately small set of pieces.

### Open canvas

Compose is an open canvas like Figma. Everything on it is an element the user can add, select, move, rotate and delete freely:

- **Marbles are elements.** Add Marble (O) places its release point on the canvas and creates its row in the timeline. A marble shows its live trajectory and the dots of its marble's hits.
- **Pieces are placed anywhere.** Platforms, windmills and tunnels are drawn or dropped at any point on the wall and act physically at once. Placement on a trajectory is a convenience, not a requirement.
- **Live preview while dragging.** Dragging any element into or across a trajectory recomputes the run continuously and shows what will happen if the element stays there.
- **Every hit has a dot on the run line, where the marble is at the hit's time, and the dot carries the hit's status**. Every dot looks the same, a solid dot with its small outline ring. Open is the marble's color, and the next one pulses. On time is green at the same size, with no pulse. A hit that needs attention is a little larger, amber for early or late, red for Missed, Stopped or Blocked, and pulses like the next open dot. Reduce Motion stops the pulse. Badges are for what has no dot of its own, such as Blocked scenery.
- **A hit and its platform are linked, not one thing.** Clicking a placed dot selects the hit: the dot gets a ring, its diamond is selected, and the inspector shows the status, Note and Time and a row that selects the platform ("Platform 7"). Clicking a platform selects the platform: it is outlined, its inspector is as ever with Plays linking to the hit, and the hit's diamond takes a lighter highlight. Neither selection marks the other on the wall. Open dots win over pieces within 10 px; of a placed dot and a bar the nearer wins and a tie goes to the bar, so bars stay easy to grab at low zoom, and hover shows the winner. Pressing a placed dot and dragging moves the platform: a drag on the wall never changes the music.
- **Arrows have one meaning each.** ← → move: with the bar showing they're its ◀ ▶, from note to note and stopping on long rests; otherwise they step notes on the marble in focus, or from the playhead across every marble. ↑ ↓ always tilt (⇧ 5°) the selected platform or the platform of the selected note, and a hold or quick run of presses is one undo step. So after ◀ its platform can be tilted at once.
- **Fixing an off-time hit.** Fix sits under the status on an amber or red hit, from the hit or the platform. Tooltips name the cause ("Lands 12 ms after the note. Platform 7 sits off its dot: Fix, or drag it back"): a tilt stays local (see Editing earlier pieces), and Time ("moves the note in the song") changes the music.
- **⌫ removes what is selected, and never takes music first.** A marble goes with its pieces and hits in one step, as Delete Marble does, and the last marble stays and says so. With a hit selected it removes the hit and its platform in one step. While the project has a song, a hit with a pitch becomes Backing and keeps sounding, so only a second ⌫ takes the note; a tapped hit goes. Clicking in the piano roll makes ⌫ its own, and there the note goes. **Delete Note** in a hit's menu removes the hit, its note and its platform in one step; pieces that follow the marble tie to the nearest hit left, as in a hand-over. A selected platform goes on ⌫ and its hit stays.
- **A click on an open dot selects its note.** The bar is then on it with its hint, or on the rest before it when that isn't filled yet. With the Platform tool armed the piece is already chosen, so a click on a dot adds it at once. A right-click on a dot opens the note's menu.
- **After tapping or importing, the next step is on screen.** When tapping stops or a song is imported, the Wall glides to each marble's next open dot if it is out of view, with room for the bar, and with the releases when they fit at a readable size.
- **A drag keeps what a platform plays.** Dragging a platform that plays a note keeps Plays, with a ghost where it was. Within its note's reach it slides along its bar, which changes nothing in the run. Further, the platform before it sends the marble to the new spot and the next ones bring it back on its run, so the platform goes where it is dropped, its note stays on time and the rest of the track stays. A platform right after a Rail has no platform to send the marble there and stays on its line. Only Detach, ⌥ or a drop more than 25 cm from its note frees it, with a notice and Undo. Fix or A sets its tilt and bounce again.
- **A duplicate never changes the run.** ⌘D puts the copies on the nearest spot clear of every marble's path and every piece, checked with a what-if run; without one nearby they go beside the run at their height and the notice says so, and if even that breaks hits nothing is copied.
- **Two ways to attach, both optional.** *Anchoring* attaches any element to a moment on a marble's trajectory, so it follows upstream edits; it plays no note. The moment is stored against the marble's hit before it, or its first hit when it comes earlier, so a marble needs at least one hit to anchor to. *Linking* is only for music platforms and only onto hit dots, which are special: clicking a dot with the Platform tool, or dropping a platform on a dot, links it so it plays that note. Unlinking or unanchoring keeps the element where it is. There is no separate pin: a linked or anchored element follows its hit, and an element is kept in place by detaching it with the Detach button on its tie row. Windmills, rails and tunnels never play notes.
- **Rails and tunnels are drawn with one vector tool, Rail**, like Figma's pen, not a freehand brush: click to add points, drag to pull out curve handles, Return or a click on the first point to finish. Points and handles stay editable afterward. A drawn path is a rail by default (B); U arms the same tool for a tunnel. The inspector's Rail | Tunnel control switches a path piece between both in one undo step, keeping its path, its free pose or anchor and a custom name; the other type's parameters start at their defaults.
- **The bar is the one way to build a note.** See The bar below. Nothing else on the wall adds a piece, except the tools and Insert's Elements. A with a platform selected is **Fix**, which solves that platform again; with nothing selected, the whole run. R repeats the last platform's tilt on the next note. The tool rail beside the wall holds the tools.
- **Transport lives in the timeline.** Go to Beginning, previous and next hit, Play and an LCD time readout that accepts a typed time sit in the timeline header, like Logic's control bar, with Final Cut's zoom slider at its right. A typed time or a step to the previous or next hit (← →) brings the marble there into view, like Figma's zoom to selection, with Follow on or off: the hit dots struck at that moment and their pieces, or the focused marble between hits. The view glides there at the same zoom in about a third of a second (at once with Reduce Motion), and does not move when they are already in view; with Follow off, dragging the playhead and playing never move the wall.
- **Audio Scrubbing**, like Logic's Scrub and Final Cut's audio skimming: while stopped, pressing and dragging the playhead on the ruler plays the Song where it is, to find a sound such as the bass by ear. Each snippet lasts 120 ms with 8 ms fades, one at a time: the next starts when one ends, at the latest position, and only if the position changed, so holding still is silent after the first. Release stops it at once. It plays the rendered soundtrack with its Mute and Solo, MIDI or audio, so soloing Bass scrubs only the bass; a soundtrack that isn't rendered yet renders first and the drag is heard once it is ready, and muting or soloing while stopped renders it soon after, so the next drag has it. While playing, a drag keeps restarting playback at each position instead, with no snippets. Typed times, stepping and other jumps of the playhead stay silent. On by default; **Audio Scrubbing** in the timeline's ⋯, the View menu and ⌘K turns it off, remembered on this Mac, with no button.
- **Zoom to Fit (⇧1) shows everything in the run, not the film length**, like Figma's fit to the layers: the releases, the pieces and the hit dots up to each marble's last placed hit and the next open dot. The free fall after the last one and the rest of the length are left out. The timeline's Zoom to Fit (⇧Z, in its ⋯) likewise fits the song, up to its last hit plus `SONG_TAIL`, when the length runs on past it. Zoomed out until a default platform is under about 16 px, on-time dots step aside so the track shows; a hovered or selected one and every dot that needs attention stay. **Zoom to 100%** (⌘0) shows the physical size. Coming back from Film keeps the view.
- **Film shows hitboxes on demand.** Compose draws pieces as their hitboxes. Film draws skins, so a selected piece shows its hitbox as a thin green outline over the Draft Preview and Blender's preview frames, and **View › Show Hitboxes** (⌘K too) outlines every piece, like Unity's collider gizmos. The outlines are the simulation's colliders in the marble's plane, projected through the film camera, a windmill's arms as they turned by the playhead.
- **Flat by default, 3D to look around, Camera to set the shot.** Track is the skeleton: 2D flat and free like a Figma canvas, following the marble only with Follow; 3D, a free look around the same wall, with the same Follow and zoom; Camera, through the film's camera with the scene dimmed beyond the frame. 3D and Camera use the Pegboard look with Rails, Tunnels and Bowls as real meshes at the marble's depth on thin posts. The Camera layer, its timeline row and inspector are in Track and in Film and edit the same camera. Film is what the viewer sees, where placement, rhythm and framing are judged before anything renders; Format and framing problems live there, and a framing problem opens Film with the Camera layer selected. 
- **Follow**, like Logic's Catch Playhead, is a toggle in the canvas corner in 2D and 3D (F, ⌘K Follow Marble in View), off by default and remembered per project on this device as view state, never in the project file. While it is on, the view glides with the focused marble (the selected one, or the first) whenever the playhead moves, playing or scrubbing, the way the film camera does: a critically damped spring moves the view's center, a dead zone of about 70 % by 40 % of the view lets bounces and zigzags pass without moving it, the view looks 0.3 s ahead along the marble's velocity, the zoom never changes and the view never pages; the marble itself stays at least 10 % inside the edge on a fast fall. Panning or zooming by hand (wheel, pinch, drag, Hand tool, Space-drag, ⌘+ and ⌘−) turns Follow off, and the toggle shows it; the Zoom to commands keep it.
- **Speed is a project setting.** Compose's Scene inspector sets Gravity (gravity scale, 0.05 to 2). New projects use a quarter of Earth's gravity: slower speed gives smaller hops and denser columns while every linked hit stays on time, about 10 bars in frame on `reference-20`, against 6 at 0.5. Platforms keep their own bounce. Very fast rhythms need care at the default: a mirrored zigzag of hits 0.3 s apart hops only about half a bar, so its bars overlap, and a Zigzag Pattern at its default Width plays hits 0.3 s apart but needs Width 8 cm at 0.25 s.

### Repeat Range

Repeat, like the Loop button of video editors, loops a range while editing: C or the transport's toggle turns it on with 4 s from the playhead. The range appears on the ruler only while it is on, so moving the playhead can never start one; drag it or its edges to change it. Playback jumps back at the range's end, and Play starts inside it. Turning it off removes the range. It is a preview for this session: never saved, never in the film.

### Music rows

Each marble has one row, shown as its layer's row in the timeline. A note of the song belongs to exactly one place: a marble, which strikes it as a hit, or **Backing**, which is heard in the film and needs no piece. The timeline's left column is **Layers**, the same layers as the sidebar:

- **One row per song** on top, for each song file or Backing notes: the row reads Song with the file as its subtitle ("jingle-bells.mid · 120 BPM" or "take.wav · 0:35"), a waveform with beat ticks for a recording and an overview of every note for MIDI, marble colors and Backing in gray. A song with notes expands into a piano roll of every note, the one place notes show by pitch; a recording stays a flat waveform row with nothing to expand and every hit drawn on the waveform as a tick in its marble's color, so hits can be judged against the sound. Mute and Solo sit in its header. Click selects a note and plays it, Shift-click adds one, dragging a note moves it in time and in pitch, dragging its right edge changes its length (up to 0.6 s for a marble's note, 4 s for Backing, as long as each can sound), dragging on empty space selects a box of notes. A double-click on empty space adds a note at that pitch and time, nudged to the nearest sixteenth when close to it (⌥ keeps it exact), 0.25 s long or as long as the last note resized, for the marble in focus or else the first one, or Backing without a marble: a hit with a pitch, so its dot appears on the run, as one undo step. ⌫ removes the selected notes, with any platform that plays them. Roll keys take a soft tint of the marble playing them, gray for Backing, while playing and scrubbing, and release with a short fade at the note's end; muted notes stay dark, and Reduce Motion leaves it on because it is state, not motion. Pressing 1 to 9 hands the selection to that marble in layer order and 0 makes it Backing; the context menu lists Play With · each marble · New Marble · Backing. A project has any number of songs, MIDI and recordings alike, and a marble needs none. Song… under the + beside Layers, Import Song… (⌘I) or a dropped file adds one: the first so its marble is released at 0, a MIDI file's first note at 0:00.50, a recording at 0 or later only as far as its first beat needs; the next at the playhead, and its notice says so. With several songs each row leads with its file's name. **Replace Song…** gives a song a new file of its kind; a recording keeps its start and its tied hits. Each song's row expands on its own into a roll of its own notes: the hits tied to it and its Backing. Build Entire Track builds every marble's open hits, whichever song they belong to. **Delete Song** (⌫ on a Song layer, its context menu) removes that song's file and Backing as one undo step with a notice and Undo ("Deleted Jingle Bells.mid and its 40 Backing notes. The marbles keep their hits."); it asks "Delete Jingle Bells.mid and its 40 Backing notes?" · Cancel · Delete first only when Backing notes would be lost.
- **One layer per marble**: name, hit count, Mute and Solo once it has notes that play, and its hits in a flat row drawn by timing status: a green diamond On Time, an amber circle Early or Late, a red square Missed, Blocked or Stopped, a hollow diamond Open. Shapes differ so color is never the only signal; the tooltip names the status. A marble's row stays flat and never expands: a hit's pitch is edited in its inspector or in the Song's piano roll. Right-clicking a hit offers the same Play With entries.
- **Camera** and **Titles** last, in Film only: the shots as markers and the titles as clips. Compose leaves them out so its timeline stays about notes and hits.
- Handing a note to another marble or to Backing keeps the note and its ID, as one undo step. The platform that played it goes with it: to the other marble's run, or removed for Backing, and a notice says which. A piece that follows the marble at a moment keeps that moment, tied to the marble's nearest remaining hit, and stands Free only when no hit is near enough. A Free platform is on the wall from the start, so the run after it can change.
- The note summary at the left of the timeline header reads "12 of 12 notes on time", or "2 notes need attention" when hits are early, late, missed, blocked or stopped; clicking it selects the first such hit's platform, frames it and moves the playhead there. Open hits count toward the total only.
- The hit inspector's Played By section has a Marble pop-up with every marble and Backing; choosing one hands the selected notes over like the number keys. A Backing note shows as "Note 3" with its pitch, velocity and time.
- A hit has a time and a sound, either a pitch or a sample; MIDI notes also keep their length
- MIDI import keeps every note. Marbles play the notes of the checked tracks: a marble plays one note at a time with at least 180 ms between hits, so chords spread across marbles up to the chosen count, or keep their top note. Every other note becomes Backing: chord notes no marble can take, notes too close to the previous one, and the unchecked melodic tracks. Drum tracks are left out, since the instrument bank has no drums. The import sheet shows a row per marble and one for Backing with their note counts.
- Audio import suggests hits from detected onsets: **Add 193 Suggested Notes** on the marble's timeline row menu and ⌘K, and as a link in the row's empty hint while it has no hits. Tap-along records hits while the song plays. With playback stopped, T places a hit at the playhead and never starts playback, so a spot found by scrubbing gets its hit. Before the earliest time the marble can play one (at 0:00) the hit lands there and the playhead moves with it, so no Too Soon hit lands at 0:00; with the playhead on a hit the next T lands 0.5 s later and moves it too, so pressing on keeps adding. With no pieces in the project yet a marble is released 0.5 s before its first hit, never before 0:00, and follows that hit when it is added, moved or deleted, so a first hit at 0:03 isn't Out of Reach. The soundtrack is rendered once while the window is idle after a project opens, so the first Space starts at once.
- A project without a Song opens normally and everything works, hits and tapping included, silent but for notes a marble has of its own; Song… stays under the + beside Layers, and Export Film… warns ("Export Anyway") without blocking
- The user decides where the run ends. There is no fixed length limit in the UX.
- A MIDI import into a project without notes sets the length to the last note plus 0.4 s (`SONG_TAIL`); an import next to existing notes only lengthens it. Fit to Song sets the same length.
- **A Bowl lengthens the ending.** One rule (`filmTail` beside `SONG_TAIL` in `music/marble-commands.ts`) sets the tail: when every marble that plays last, those whose last note falls within 1.2 s of the song's last note, has a Bowl that catches it, the film ends 0.1 s after the last of them leaves the frame, between 0.6 and 1.5 s after the last note (a Bowl holds it, so 1.5 s); else 0.4 s. A Bowl that misses keeps 1.2 s (`BOWL_TAIL`), also the length until the first measurement. Fit to Song, the import and the automatic fit all use it. The time comes from a what-if run past the end through the follow camera (`bowlExit`), so nothing new is stored: Fit to Song measures on the click. Whether the Bowl catches its marble is the problem model's: "Melody misses the Bowl" when the marble falls past it, bounces out or the film ends first
- **The length changes only when typed, dragged or set by Fit to Song.** Typed or dragged it stays between 0.5 s and an hour; a longer song keeps its own length and goes no further. Edits of notes and pieces never move it, and **Fit to Song** on the ruler's menu, the timeline's ⋯ and ⌘K is offered when the song ends more than 1 s before it or runs past it. Two things stretch it because nothing could work otherwise, and say so where they speak: a Bowl that Build Entire Track or Add Bowl places lengthens a film that would end before the catch, never shortening one; taps that run past the end lengthen it when tapping stops. An import sets it, as above. While T taps along, playback runs on to at least 0:12 in a project that still has that length, like Logic recording past the project end. The camera holds on the last hit and the marble that struck it leaves that held frame 0.47 to 1 s later, so the film ends on the marble, like the reference shorts that end right after the final note. The soundtrack fades out over the last 0.4 s so a note still ringing is not cut off

The sidebar's Layers holds everything in the scene, like Blender's Outliner; settings that aren't things, such as Gravity and Format, stay in the Scene panel. The timeline holds only what changes over time, like Blender's dope sheet, in the same order: the Camera's shots, the Song, the marbles with their hits, and in Film titles with their In and Out. Pieces, the Wall, lights and Decor have no timeline row; a light gets one only once it animates. The Scene heads the sidebar's list. Both tabs list in one fixed order: the Camera with its shots, the Wall, the Song (when present), each marble with the pieces it plays or that follow it in hit order, then the group **Track Pieces**: those no marble plays or follows, which marbles can still hit. Film goes on with Lights, Titles and Decor, and the Song and marbles stay selectable there for skins. A group with nothing in it has no row: Titles and Decor appear with their first item, added through Insert. Camera framing problems found in Compose stay in the note summary and jump to Film with the Camera layer selected. Selecting a layer in either place selects it in both and in the inspector, for the Song, each marble, the Camera, each shot and each title; what has no row in the timeline selects in Layers and the inspector. Several titles or Decor items selected show their count. Each layer owns its settings in the inspector: the Song its file, tempo, Backing and its Sound, Replace Song… and Delete Song; a marble its color and, in Track, its Start Position; the Camera Follow Marbles with Distance, Turn, Tilt and Sway, and the framing problem at the playhead; a shot or a title its own; the Wall its Color in Track, which the plain Pegboard wall takes there and in Film under the skin None, and its Skin, Wall color and Background in Film; sections run Position, Shape, Appearance, then the rest such as Physics and Plays; a light its Color, Strength, Side and Height (Key Light with Reset to Brass, an added Light with Delete Light). The Scene (nothing selected) keeps what the whole film shares: the Theme row and Format in Film; Gravity (every marble at once) in Compose. The length is the transport's second time, which a click types, and the ruler's end marker; Fit to Song is on the ruler's menu and in ⌘K. Quality lives in the Export sheet, which opens on Draft until the person chooses for this project, and then on that choice. **Insert** (+ in the tool rail, ⇧I) holds what you place on the wall, with previews: the track in Compose (click arms, drag drops); Decor and titles in Film (a Decor tile waits for a click on the wall, as Track's do, Particles are added at once, and a drag places), with Packs… at its foot. The + beside each Layers heading, in the sidebar and in the timeline's column, adds a layer from one list: the song, a marble, a shot, and in Film a title, a light or Decor.

Sound depends on the source:

- **A hit can belong to a song.** A hit tied to a song moves with it; without a tie it is the marble's own, and stays where it is. Hits are tied when they are imported, tapped along while a song plays, added in a song's piano roll, added with a double-click on a recording's waveform (for the marble selected last, nudged to the nearest beat found, ⌥ keeps it exact) or added as Suggested Notes. A double-click on a marble's row adds one of its own. The marble's **Song** field does it for all its hits at once, reading a song, None or Mixed, and the marble's timeline row shows a chain with the song's name while any are tied. Detaching leaves every hit where it is, as one Undo step, so a later move of the song leaves them. The hit inspector's **Song** field ties or unties the selected hits; Delete Song unties its hits and they stay. On a marble's row a thin line runs under the hits tied to a song, and stops at a hit of its own, so the row says at a glance what moves.
- **Moving a song.** A song's notes or waveform sit on a clip in its collapsed row. Dragging the clip moves the song, and live with it the hits tied to it and their lines, on a 25 ms grid, as one Undo step; the **Start** field in its inspector does the same for a typed time. Its Backing moves too. A marble that plays only this song starts that much later, so its whole run moves, the pieces stay and every hit stays on time. A marble that also has hits of its own keeps its start, so Problems show where its track no longer fits, and Fix can take it from there. The length stays, as with every edit: a move that takes hits past the film's end says so with Fit to Song, and those hits read Missed with that reason until then. A song can't go so early that a note or a marble that goes with it would start before 0. A recording can: what falls before 0 is left out of the film and the preview, like trimming a clip, and its Start reads "−0:02.00".
- **What sounds.** A MIDI Song's notes play through their marble's sampled Sound, set in the marble's inspector. A marble's note lasts its own length up to 0.6 s and ends at the marble's next note. Backing plays on its own channel with the notes' MIDI lengths, in the song's first MIDI program when the instrument bank has it, otherwise piano. A hit without a pitch plays nothing, while editing or in the film. A hit tied to a recording adds nothing, since the recording holds it; a marble's own note plays with its Sound, with or without a song. The same sounds render the film soundtrack.
- **Mute and Solo live on a marble's row and a song's row**, as view state for the session: each opened project starts with everything on, they are not saved and have no Undo. A marble's take out or isolate the notes it plays. A song's cover everything it plays: its recording, its Backing and the marbles' hits tied to it. They change what plays while editing at once. **What is muted is also left out of the film's soundtrack**, and the export sheet says so in a quiet line ("Bass is muted and left out of the film's sound."); solo is for listening and never shapes the film.
- **Timing is shown, not heard.** As a marble lands a hit during playback its dot in the timeline swells and flashes in its status color (green On Time, amber early or late, red Missed, Blocked or Stopped), and a ring in that color flashes on the wall where it lands. A hit's tooltip names its offset ("On Time (+3 ms)", "12 ms Late"). Flashes never re-render the rows, so they stay cheap at normal playback.
- An imported recording already contains the music. Hits only mark when the marble should strike, and no extra sound is added.
- **A recording whose file is gone is a Problem.** "take.wav is missing" says the film would play without it. The app looks for the file again every 2 s while it's gone, and once it's back the Problem goes and the recording plays, with no restart. A recording already loaded plays on from memory.

### Pegboard view

The track lives on a wall. Pieces move in the wall plane, rotate only around the wall normal and keep a fixed distance from the wall. The marbles are locked to the wall plane, which keeps trajectories predictable.

Track's 2D, 3D and Camera views show the same wall: 2D faces it, 3D tilts it, Camera looks through the film's camera. It is calm birch, or the Wall layer's Label Color, with real peg holes every 2.5 cm that grow with the zoom and fade out far away.

The wall shows a dot grid like FigJam, drawn as pegboard holes. Its spacing adapts to the zoom level and doubles as a ruler at real scale. The grid is only a visual signal that Compose is a draft, not the final scene; nothing snaps to it. Pieces use flat, toy-like colors per type, following [marblie](https://github.com/younghoonam/marblie).

Rotation follows Figma: dragging rotates freely around the hit point with a live angle readout, Shift snaps to 5° steps, arrow keys nudge by 1° and Shift with an arrow by 5°. Double-clicking the readout accepts an exact angle. Brackets adjust their length to reach the wall, so a piece never leaves its hit point.

### Pieces

| Piece    | Kind    | Purpose                                                        |
| -------- | ------- | -------------------------------------------------------------- |
| Platform | Music   | Main hit surface; linked to a hit dot it plays that note        |
| Rail     | Scenery | Visible path for long gaps and rolling                         |
| Tunnel   | Scenery | Physical tube that hides the marble; length and slope set the travel time |
| Windmill | Scenery | Moving piece the marble strikes; spins with damping or a motor |
| Bowl | Scenery | Collects the marble and holds it, so the film can end on the catch |

Only platforms are music pieces. Scenery never uses up a note: a marble striking a windmill or rolling along a rail is a plain contact, never a hit and never a miss. Scenery is either free on the wall or anchored to a moment on a trajectory, which is how the windmill tool places a windmill: like a rail, on the trajectory, not on a hit dot. The assists never put scenery on a hit. A platform can be anchored too; it then follows the trajectory and plays no note. Free and anchored pieces are environment the marbles may strike; only another marble's music pieces, and the other marbles, count as stray contacts.

A Rail holds one path or several with gaps between them, like one Blender curve with several splines: one row in Layers, one Hitbox, one Skin. The inspector's **Layout** generates the paths from Turns, Width and Drop: **Drawn** is the Rail tool's own path, **Curve** one smooth curve, **C** one wall that curves round, **Chain** curved turns one under another, **Switchback** straight runs one under another.

The Switchback layout holds the marble in a narrow column: it drops in at the top, rolls down a leg, falls through the opening at the leg's end onto the next leg, rolls through the rounded bend at the wall and back, and leaves through the last opening. Each leg is one bent wire, wall into bend into leg, so the marble rolls through the turn instead of knocking against a corner. Leg count, slope, width and bend radius set how long it holds and how far the marble descends meanwhile. The bar offers one for each long rest; it is not on the piece keys.

A Bowl collects a marble, like the catcher in the reference short: the marble drops into it and stays, its rims curling inward. It is a piece like any other, added by hand or by an agent and deleted the same way; no setting swaps it for anything. Build Entire Track ends each marble in one, and starts each bare marble on a short Rail, at least 10° and 6 cm, so it rolls into its first note instead of falling. That Rail is ordinary too and can be deleted. A marble has at most one Bowl: dropping or clicking another onto its fall moves its own. It sits in the Insert library under Pieces and its tool anchors it where the marble's fall is clicked or dropped, like a windmill. **Add Bowl**, the Bowl tile under + in Insert while a marble that plays last has none (Add Bowl for Bass with several) and in ⌘K, tries spots 7 to 35 cm below the last note's dot with the backstop on either side and keeps the first where a what-if run shows the marble landing and staying in it, no hit that played breaks, no other marble touches it and the marble touches no other marble's piece; it fills Jingle Bells and Reference 20 in about 0.2 s each in Node. Layers list it last under its marble. Its inspector shows Position, and Size and Thickness in Shape; the header pill says Catches (with when it lands), Missed, Bounces Out or Blocked, and **Place Bowl Again** sits under a bad pill, checked by its what-if before it is offered. A Bowl plays no note, so Color by Note never colors it.

Rails and tunnels shape the path through long gaps; they do not have to deliver the marble to an exact point. The user places one onto the trajectory and adjusts its length and shape while the live trajectory shows where the marble goes. After it, the marble is in free flight again, and the next hit's platform is placed where the marble is at that note's time, so the hit stays on time.

Each piece type is one self-contained definition with a physics shape, a few parameters and a default skin. New projects use a kit one and a half times the Marble Race Kit's size: 24 mm marbles and platforms 3 cm long and 15 cm deep on long posts, spaced as 9 cm bars (`references.md`). Depth is visual. Parameters are physical: platform length and thickness, rail radius, tunnel length, windmill blade count, blade length and damping. Adding a piece type later means adding one definition.

Each marble has a release with its own position on the wall and time on the timeline, independent of the first hit. The MIDI import releases each marble 0.5 s before its first note, a short drop, so the film does not open on a long empty fall. Like a clip in a video editor, the release can be moved earlier to leave a gap before the first hit, and that stretch can hold any pieces.

The time is a ring on the marble's timeline row, the one the marble has on the wall, which drags in time, and **Start** in its inspector's Timing. The run follows live as a what-if on the wall and the row, and the drop is one Undo step. A longer fall means a faster arrival lower down: pieces that play or follow a note slide with it and stay on time, about 13 cm lower for the first 0.06 s of an 0.94 s fall on Jingle Bells, and 49 cm higher for 0.24 s less. A free piece stays where it is, so the new run can meet it. A marble held on a start rail keeps its timing when it starts earlier and is late when it starts later. Past the first note the time is kept, as asked: the chip says "Notes 1 to 3 come before this start", and those notes keep their hits and platforms, read Too Soon or Missed in the note summary and on the row, and a notice says so with Undo and Fix.

### Patterns

Patterns make building tracks easier: a shape built over a stretch of notes or a rest, on a song with or without pieces, chosen in the bar's dropdown. Track only; one marble worked out at a time. What Build Entire Track places shows in the strip as plain Groups: a Zigzag, a Rail or a neutral Run of the marble's notes.

Each marble's row has a slim strip, 16 px, above its hits: nearly invisible while empty. Selecting a stretch: drag over hits in the row, or drag out a range in the strip, also over silence. A strip range over notes selects those notes. The bar then offers Zigzag and Staircase for notes, and Curved Rail and Switchback for a rest. On one note the stretch is the phrase from it: up to eight notes, until a gap over 1.2 s.

A Pattern is checked before anything changes. Opening the dropdown asks each kind in turn, filling in with ✓ or a reason; a pointer or ↑ ↓ on a row shows its ghost, panning to it isn't needed as the view keeps the note in sight. Choosing a row keeps that ghost and the label becomes its accept. Accepting makes a Group, one Undo step. A kind that doesn't fit says which note and why, and nothing lands. Agents and a Group's own settings go through the same check with progress and Stop in the notice: if it doesn't fit, nothing changes, the notice names the note and why and offers what fits instead ("Use Notes 12–15", "Use Width 12 cm"). ⌘Z while fitting is Stop. In Layers it's a closed row under the marble; in the strip a block. A click on the block or the row selects the Group with its pieces; its edges resize it, which fits it again (a Curved Rail always fills its silence, so it has none). The inspector shows Width, Bounce and Tilt limit, like Blender's Adjust Last Operation. Using them fits it again, keeping the pieces' skins and Depth. Delete takes the Group's pieces and the Group.

A live Pattern's pieces don't edit one by one, like Blender's Array modifier: clicking one in Compose, on the wall or in Layers, selects its Group, and dragging or tilting it changes nothing and says once "Part of Zigzag." with a **Flatten** button beside it, in the bar when it shows, also in its right-click menu, on its block in the strip and in the Group's inspector; from the notice or the menu, the piece a person went for stays selected, so a drag works right away. Nothing flattens by itself. Agents get "Part of Zigzag. Flatten to edit it." from `project.execute`. A Skin in Film and Depth under Shape in the Group's inspector stay free. **Flatten** in the Group's inspector, like Blender's Apply, keeps the pieces and removes the Pattern, one Undo step: they stay a plain Group of the marble, selected, nothing fits them again, and a later Group fits against them as a fixed start.

A **plain Group** has no Pattern: ⌘G or Group Selection in Track's right-click menu makes one of the selected pieces, in Compose or Film, and ⇧⌘G or Ungroup takes it apart; both one Undo step, like Figma. Selected as a whole it reads by its name, and when it plays a run of a marble's notes the bar offers to change it. It has a row in Layers, under its marble or, across marbles or of free pieces, under Track Pieces, and a block in the strip when its pieces play notes, with no edges to drag. A click on the wall selects the whole Group and a drag moves it; ⌘-click or a double click reaches one piece, as a click on its row in Layers does. A piece leaves any plain Group it was in for the new one; a live Pattern's pieces can't be grouped, and say so.

On a song already built, a Pattern follows the way the track goes: it keeps the height the track has and ends where the next note waits, so what comes after stays where it stands. The next platforms take up the change in speed where they can; otherwise what follows moves with the marble, which the check says. A rail already holding a silence stays and joins the Curved Rail's Group. A hop too long for a bounce gets a rail inside the Pattern, as Build Entire Track's do.

The notes before a Pattern don't have to be built. A marble with nothing before the range starts just above it: it's released up to half a second before the first hit and after the note before it, and the notes before stay Open, not Too Soon. A Pattern on those notes later moves the release back and fits what follows again. A Curved Rail over the silence before a marble's first built note opens the track: it's the marble's start rail, and the marble is released at the range's start, where it was. With pieces before the range and notes with nothing between, the marble falls past them: if that fall is a meter or more the first hit is out of order, and the check says which hits to build first.

Without a Width set, the app picks one that fits: for a Zigzag what the track's own hops span on a built song, the usual one, then a little wider; for a Staircase steps that stay in frame. A Width set in the inspector or by an agent is what's asked and is never changed: when it doesn't fit, a nearby one that does is offered. The same goes for what can't fit at the hits: "The 0.21 s hop needs more than 40° of tilt at Width 15 cm." The Tilt limit is 40° unless asked otherwise; bars past 40° are allowed once asked for, with a note. Nothing falls back silently. A live Group's verdict isn't stored: its block and inspector work out from the run which of its hits don't play.

Changing Gravity fits every marble's live Patterns again, with it in one Undo step, and Stop takes the change back too. Changing a Group fits the later Groups on that marble again when the marble now leaves it differently, in one Undo step, with progress and Stop in the notice. Stop changes nothing, and an edit made meanwhile stops it. A later Group that can't fit any more refuses the change too; only Gravity's re-fit keeps it and says so first. A Group with several marbles' hits selected is made per marble, and the notice warns if pieces touch.

Bars steeper than 20° on average below Gravity 0.9 get a line in the Group's inspector: Gravity 1 about halves that. Gravity is never changed for you, since it sets the whole film's pace.

### The bar

A track is built note by note in the floating bar, centered at the bottom of the wall. It shows only for a selected note, several notes, a rest, or a piece tied to one of those, and a new track with nothing built opens on its first note, so it's there at once. It hides while playing, dragging, drawing and building.

Its groups, with separators:

- **Where:** ◀ Note 12 of 51 ▶, with ← → as keys. The arrows only move, and also stop on a long rest (Rest · 2.0 s). Moving changes nothing and keeps the note above the bar. Several notes read Notes 12 to 19.
- **What:** on an open note, Add Platform ▾; at a rest, Add Curved Rail ▾. On something built, its type ▾ and a status badge in the same shape and color as its diamond on the row, a word only when it's wrong, and **Fix** when there's a problem. In a Pattern, Part of Zigzag · **Flatten**.
- **Adjust,** on a single platform: Tilt as a scrub field, which ↑ ↓ also turn, and Flip only at the end of what's built, where it chooses a direction and no later note depends on it. M is its key.

**The hint.** The wall shows the current choice from `propose`: a platform's shape at once from the note, then its answer just after, with where the marble goes and its next dot. Moving on cancels it. Nothing changes until it's accepted, and accepting applies exactly what it showed.

**Enter accepts and moves on,** as one Undo step; a press before the answer waits for it, and takes it if it fits. ◀ goes back to adjust. On something built with nothing chosen, Enter just moves on. N is the same as Enter, and with nothing selected opens the bar where building goes on. ⌘Z is the normal Undo, and an Undo of what the bar landed goes back to where it stood. Esc takes back a choice, then the selection.

**The dropdown** (▾ or Tab, then ↑ ↓ and Return) offers only what fits the selection: on an open note Platform, Zigzag · 8 notes and Staircase · 8 notes; on a rest Curved Rail and Switchback; on a built note or a range Change to each of them, Rebuild From Here and Remove; and Build Entire Track last while notes are open. Kinds other than the chosen one are checked only while it's open, filling in with ✓ or a reason. One ghost shows, of the row under the pointer or the arrows. Choosing a row makes it the label: Change to Zigzag · 8 Notes ↩. Changing a built note says what happens to later notes first: "Later pieces stay.", "2 later pieces change to keep notes on time." or "Notes 42 to 51 stop playing. Their pieces stay.", and something that breaks notes reads Remove Anyway, never a plain accept. A rest whose Curved Rail doesn't fit says why; Enter then opens the dropdown, and ▶ goes on with no piece.

**Past the built notes** the bar offers **Build Up to Here,** which builds up to and including that note as Build Entire Track does, as one Undo step, and leaves the rest open.

**What's about the note lands in the bar,** in a line above it: why a note can't play, with its fixes, what a change or a Tilt did to later notes, with Undo. Everything else stays in the notice, which stands above the bar in the same lane. Quick Help's panel sits above the bar on the right.

Agents ask the same thing through `build.propose` and `build.accept`. Assists run in a second simulation worker, so the live trajectory never waits for them, and each kind of assist keeps only its newest question.

**Build Entire Track** is last in the bar's dropdown while notes are open, in ⌘K and the Track menu, and on ⇧N; an agent runs `build.track`. It works at the film-frame zoom, so its pieces read as they land, and ends, for a person or an agent, at that zoom with the playhead at 0:00 and Follow on, so Space shows what was built. It works like a patient person. Marbles are built together in time order, so each keeps clear of what the others have built so far. Each step takes the first option that keeps every placed hit on time, every marble on its own pieces, the next dot in its band and near the shared pace: a rail for a long gap, Continue, Mirror, Next, a wider search. When none does it turns the previous platform, then another marble's platform in the way, leans this one by hand, and backs up a few hits. A stuck hit, a stretch the camera loses a marble in, a dot off the pace or a marble no Bowl catches sends it back a second or more to turn a platform and go on from there. Only when that keeps failing does it start over with the releases a few millimeters over, for marbles that have no pieces yet.

- **It shows the work.** Pieces appear on the wall as they are found and the view follows. The notice reads "Building track · 42 of 115 hits · about 40 s left" with Stop, the one place for how far it is; the note summary reads Checking…. No panel opens.
- **One undo step**, whether it finished or was stopped. Stop or any other edit ends it between steps; what it built stays.
- **Your pieces stay.** A piece already placed is turned only when nothing else solves a hit, and the notice says "Turned 1 of your platforms". Pieces are never removed, and moved releases are named too.
- **It finishes.** A hit nothing solves gets the flattest tilt that plays it, or stays open, and the rest gets built. The notice names those hits ("2 notes need attention: Melody hit 12, Bass hit 30") and offers Fix when platforms are broken.
- **The same project gets the same track.**

Rails and tunnels can also start anywhere on a trajectory: a path drawn from a point on the line is anchored there, so the marble enters it at that moment, and a dropped or dragged one anchors near the line like any piece. A selected rail or tunnel shows an end handle that sets its length and a bend handle that curves it, with the live trajectory following the drag. The inspector reports how the marble rides it, such as "Marble leaves the rail after 1.1 s, then flies 0.12 s to Note 4".

Guardrails appear while building:

- A gap too long for a bounce offers a rail or tunnel. A gap is long when one bounce at the descent pace would rise more than 0.4 m at Earth's gravity, about 0.68 s at the pace of a 0.5 s rhythm. The height scales with Gravity like every height at a rhythm, so the threshold stays near 0.68 s at any speed.
- A dot turns red when the next hit falls outside the frame or collides with an existing piece

### Recovery

An edit that breaks the run offers its fix where the user is looking, like Xcode's Fix-its, so ⌘Z is never the only way out.

- **Every notice that reports an edit has Undo** ("6 platforms removed: Backing needs no platform" · Undo, "Added 4 platforms" · Undo), like Mail's and Finder's undo toasts. Undo shows only while that edit is still the latest; once another edit follows, the notice stays without it. A notice with actions stays 10 s, and as long as the pointer is over it.
- **One Fix.** Undo goes back; Fix mends what's there; Rebuild From Here deletes and builds again. After each edit Compose compares the hits with the run before it. When hits became Blocked, Missed or Stopped, the edit's notice gets Fix, or a notice says "3 hits are now Blocked, Missed or Stopped" with Undo and Fix. Undo, redo and Fix itself never ask. A with a piece selected, and the wand under a piece's problem pill, fix that piece; A with nothing selected, the Track menu and the notice fix the whole run. Fix always reads Fix; it says afterward what it did, or why it couldn't.
- **What Fix does for the whole run.** It rebuilds the run like the step loop built it, one problem at a time from the earliest: Auto place again for the platform before the problem (a launch into a bridged gap is tilted as if the gap were open, then its rail is suggested again, falling back to the other layout). When that fails it steps back up to three more platforms and rebuilds forward, then tries turning one of the two platforms before the problem by hand. A problem nothing fixes is left and Fix carries on after it; after three such hits on one marble it stops working on that marble. When the marble's first notes went to Backing and its first fall grew long, the release first moves to just before the first remaining note, so the marble arrives where and how fast it did before. A try is kept only when, simulated to the end, the problem moved later, no other marble lost a hit, it crosses no other marble's band, and the problem model (`addedProblems`) has no new problem apart from the work still ahead on that marble. Last, Blocked scenery gets a new bridge or moves clear, and pieces struck twice, rolled on or touching get their own Fix. A Blocked piece Fix can't clear stays Blocked and in the list: deleting is the person's call. Fix works on a copy and lands as one undo step only when the run ends with fewer problems, or as many with more notes on time; otherwise nothing changes and the notice says so ("Fix would leave 17 problems where there are 8, so nothing changed"). Progress and Stop are in the notice ("Fixing · 12 of 37 hits"); another edit stops it. With pieces waiting behind a break, a note with no piece gets a platform at once; when nothing brings the marble back the notice offers Rebuild From Here.
- **Fix for one piece.** A platform off time gets Auto place; a platform another marble hits has that marble's platform before the hit tilted, so it passes clear; scenery (windmill, rail, tunnel) gets a new bridge for its gap or a nudge the shortest way off the runs, keeping what it follows; a Bowl is placed again on its marble's fall. A change to another piece is tried on a copy first and refused when it breaks a hit or adds a problem, and the notice says so: "Moving Windmill 1 clear would break a hit, so nothing changed. Drag it by hand or Detach it."
- **What's physically wrong with a track.** Build Entire Track, the bar and Fix share one check, which the Problems read too (`track-problems.ts`): no two pieces closer than 1.2 cm in the wall plane, where skins hang below the hitbox (bars may lie over each other in the film's view, as in the reference); the real skin size counts, a marble strikes each platform once, and it bounces off: a platform is for bouncing, so the marble must rise half a marble radius off the surface, along its normal, within 0.1 s of its note. Continue may turn a copied tilt by up to 4° to clear one of these. Where a platform would touch, a shorter one is tried first. A pair that does touch, a second strike, a roll and a marble passing through a skin are Problems ("Platform 12 touches Platform 13", "Melody hits Platform 12 twice", "Melody rolls on Platform 12"), and rests after a marble's last note or rides on a rail or in a Bowl don't count. Both show on the piece with Fix. Fix puts playing first, so it can leave one of these, which the list then names.
- **Marbles may cross.** A marble stays in its band where it can, since its pieces would otherwise stand in the other's way. When no tilt fits there it may leave the band and cross another's path, as long as it touches neither that marble nor its pieces and stays in frame. The bar and Build Entire Track share this; Fix keeps a run it mends in its band first.
- **Rebuild From Here.** On a hit or a piece, keeping the zoom and ending with the playhead on that hit: keeps everything up to that hit on every marble, never turning a kept piece or moving a release, and builds the rest again with Build Entire Track's logic, keeping the skin a platform had on its note, as one undo step. A person turns one platform and the track follows. Its search budget counts the hits it builds; as it can't shift a release, its attempts differ in the turn of each marble's first new platform, each ending at the first hit nothing solves, and a hit nothing solves is forced with the lean whose next dot stays nearest its band, so no marble runs off in one long diagonal. It ends on Zoom to Fit, its notice reads the hit count as the summary does, and its time estimate appears only while the hits it builds keep coming. `build.track {from: hitId}` is the same.
- **Long gaps.** A straight Rail where one reads well, ending in the band and near the pace; the Switchback layout where nothing else bridges the gap. When both fit, each is built on for three hits and the one that goes on best wins, a Switchback costing a little more, and more again after another. `build.track {gapPiece}` tries the one asked for first. **Chain** is opt-in through `gapPiece` and the inspector, always simulated, and falls back to the Switchback layout when its turns would hold the marble.
- **Pieces another marble hits.** "Bass hits Rail 6 of Melody" in the problem list also shows on the piece: an amber badge on its Layers row and a **Hit by Bass** pill in its inspector header, both read from the same problem model (`struckPieces`), with Fix under the pill.
- **Open notes that cannot get a platform** get a status: Too Soon (before the release, or before the marble has fallen its diameter and reached strike speed) or Out of Reach (the marble fell out of the run or lies still). The hit is drawn hollow amber in the timeline, its inspector header shows the pill with the reason, Played By offers Move Release Earlier or Later when that fixes it and Make Backing, and Place Next Platform (N) explains the earliest such note of the focused marble instead of skipping it: "Note 1 is too soon for Marble 1. Move the release earlier or make it Backing." The note summary counts them as needing attention.

### Editing earlier pieces

**A drop sticks**. A platform dragged near its note lands where it was dropped: the platform before it sends the marble there, even if that breaks later hits, which the chip says ("Breaks 1 hit") and Fix offers to mend. When the spot truly can't be played, the chip and the notice say why: "Platform 4 stays where it is: the marble leaves Rail 2 here. Move Rail 2 to change its spot.", the marble's first note likewise, and a spot out of a platform's reach goes as far as it can ("Platform 3 moved 1.2 cm of 5.0 cm"). ↑ ↓ tilt draws at once like a drag, and in Layers they walk the rows and tilt nothing. Undo keeps the view.

**An edit does what you asked and nothing else**, like Figma or Blender. Moving or tilting a piece changes that piece and what immediately depends on it, and the rest of the track stays where it is, on time. Drag, ↑ ↓, inspector values, Lands At, ⌫ on a platform, Make Backing and an agent's `project.execute` all behave the same, and the whole change is one undo step. Pieces stay bound to their hit, so a marble's new way shows at once in the piece and the rail that follow it.

- **A note stays where it is, and an edit stays where it is made.** The next platform takes up a change, and a notice says so when it does: "Platform 7 changed too, so the notes after it stay on time. The later notes moved 1.2 cm with it." Later notes keep their run and move together. When that would leave the frame or run into something, two platforms take it up instead, and nothing later moves. Past what they can do the marble flies on for real and later notes wait where they were; move what's in the way or Undo, and every note is back at once. A long Switchback keeps the ride it gave.
- **The next two platforms take up the change.** The first gets the tilt and bounce that send the marble to the second's old spot, the second those that send it on as before, and how the marble leaves the second is kept. Everything after them stays put. When the bounce runs out of range the next pair takes it up, and only when no pair can do it the rest moves together by what's left.
- **Nothing is said when nothing went wrong.** The tilt and bounce of those platforms simply change; a notice appears only for a break.
- **A break stays one problem.** When nothing takes it up, the first hit the marble no longer reaches is Missed with its flight line shown, and every later piece of that marble waits where it was, its note reading **Waiting**. They never fold into a heap. The notice leads with Undo ("Melody misses Note 11. The 40 pieces after it wait." · Undo · Fix) and the problem list holds that hit, not what the flying marble does after it. A drag previews the same.
- **Fix brings the marble back.** It first tilts the platforms before the break to reach the waiting pieces, which moves nothing else. When that fails it tries the whole-run Fix on a copy for up to 10 s and lands it only if every hit plays; otherwise the pieces go on waiting and the notice says what to do: turn the platforms by hand, Undo, or Rebuild From Here.

A free piece keeps its position when the trajectory moves.

The playhead works like a rollback marker. The trajectory after it is drawn in a quieter color, so the user builds up to the playhead and continues from there; pieces keep their full color.

### Several marbles

All marbles share one physics world. The world is simulated ahead of the playhead to draw every marble's trajectory line. Marbles can collide with each other and with any piece, and a collision between marbles can be an intended effect with its own sound. Compose shows marble contacts as markers on the timeline.

Shared collisions couple the marbles: editing one marble's track can change another's timing. Compose reports newly created or removed marble contacts after each edit so the effect is visible.

One camera frames every marble, so the marbles must stay together:

- **Bands side by side.** Each marble gets a band 0.26 m wide, about three bar lengths of the default kit, and the bands sit side by side 0.26 m apart in the order of the releases from left to right; the MIDI import places new marbles that far apart. Each marble's assists keep its dots and path inside its own band.
- **Shared descent pace.** The project has a target height y*(t) that falls at a constant rate, the steady descent of the default bounce at the median hit interval of all marbles, anchored at the earliest hit. It falls at least fast enough that a zigzag's bounce stays 6.5 cm below the piece two hits back, which the marble passes on its way to the next piece of that column; at the default Gravity and a 0.5 s rhythm that is 0.30 m/s instead of the default bounce's 0.26 m/s. The assists keep every marble's dots within 0.25 m of y*: Auto place solves each platform's bounce for it, Continue drops ghosts that leave it and rails hold the marble through long notes so it leaves near it. A marble below the pace climbs back half way per hit; a marble above returns at once. The simulation result carries the pace so the film camera can follow y*.

With one marble the frame is the film frame (0.59 m at the default camera distance) and the pace is only a reference for the camera: Auto place keeps the steady speed of the default bounce, which falls at the pace rate for a regular rhythm.

A hit sounds only when the marble strikes its piece. A first contact slower than 0.3 m/s along the contact normal, such as a marble resting or rolling onto a piece, counts as missed, and the inspector's status pill shows it as Stopped.

### Long falls

A marble that free-falls more than a meter between two notes with no rail gets a tip in the checks: "Marble 1 falls 2.1 m at 0:09: a Curved Rail fills that gap". It is no problem count, since every hit still plays (prototype).

## Physics and handoff

The app owns physics. Rapier and Blender's Bullet do not produce identical results, and small differences grow along a chain of bounces until hits miss their note. One engine records the motion and Blender plays it back.

- Rapier simulates at 240 Hz, one short run per stretch between notes, so an edit runs only the stretches it reaches
- Moving bodies, marbles and windmills, are sampled at the output frame rate
- The app writes the scene directly into the `.blend` through the running Blender worker. No intermediate export format is used.
- Each piece becomes an app-owned holder object with its transform and keyframes. Its skin is a child of the holder, so rotating a piece in Compose rotates its skin.
- Every piece gets an animated hit value that rises to 1 on impact and decays to 0. Effects, reactions and the camera read it.
- A deleted piece deletes its skin, unless the skin was changed in Blender: then it moves to a detached collection, which is never drawn in a film

## Film

Film is art direction. The user chooses, describes and toggles. Blender is the editor for fine work.

The Film workspace supports:

- Selecting an object by clicking the rendered preview through an object ID pass, or the Draft Preview, like Compose. A piece selected in Layers outside the frame moves the playhead to when it plays, the film camera's way of bringing it into view
- Applying skins, effects and themes from the library
- Asking an agent to change a selected object or the scene
- Adjusting the few parameters a preset exposes, such as color, light intensity or text
- Clicking the wall to place text or a decal
- **Open in Blender**, from the title bar's Blender chip or the command palette, which opens the scene in a Blender window

The Film workspace has no transform handles. Each change needs a Blender render, so dragging would feel slow and duplicate Blender.

Film's look is unique to each project: built-in themes are starting points, and a theme is a preset of ordinary parts stored in the project. **Gift** (a wrapped box with a ribbon and a bow on its front; Color Skin, Marble or By Note, and the extra property **Ribbon Color**), **Candy Rail** and **Green Glass** (Variant Swirl) are hidden catalog skins, shown while a project uses them. **Layers › Wall › Skin** is Plain, Plaster, Pegboard or Grid.

The Jingle Bells example wears a theme **Christmas** made of these parts on Brass's render look: a neutral pale wall, a near-white Key Light with its light in a pool around the view, so the wall falls off and the red and gold are the only color, Gift platforms, Candy rails, Green Glass marbles with their own Marble Color, red Melody and green Bass, Particles, with Decor scattered. Its track comes from Build Entire Track and plays 115 of 115 notes on time.

**The Scene** is the first row of Layers in both workspaces, like Blender's Scene Collection, and an empty selection is the Scene: a click on empty space in Layers, on the wall in Compose, on the Film preview or around it, in a timeline row's empty space, or Esc selects it, so nothing stays stuck on a selection. Its inspector shows what the whole film shares. Entering Film selects the Scene when Compose's work left a piece or a hit selected, so the theme is in view; a marble, the Song and Film's own layers stay selected.

**Insert holds what you add; the inspector holds how the selection looks.** The Scene's **Theme** section in Film is one row, the current theme's picture and name; a click opens the Theme picker, the same floating panel as Insert, with a rendered still of Jingle Bells per theme (the Color by Note still for a theme whose platforms default to By Note), the current one ringed. A pick applies it and closes the picker, Esc cancels. There is no edit-theme concept: changes are made on the layer itself ("From Brass" with its reset), and picking a theme restyles everything except them. The row counts them, **Brass · 3 changes**, with a small Reset that clears them as one undo step, with the notice's Undo. Added lights and Decor are added things, not changes. Selecting a marble, pieces or the Wall in Film shows an **Appearance** section: one row with the current skin's small picture and name and a chevron, which opens a picker with the previews from `public/skins` and `public/decor` (the walls are drawn), three a row, the current one ringed, the theme's skin first, as **Theme: Gold Plate**, which also clears the selection's own properties, then Packs', the agent's and imported skins with their origin and star; every tile has its origin line (**Starter**). A search shows past about 12 items and ⌥-click applies to all of a type. Pickers and Insert stay inside the canvas area and follow the panels and the window; what doesn't fit scrolls inside the frame. The skin's properties stay below the row as compact rows. Nothing opens in place.

A new theme is a request to the person's agent, which makes it with `add_asset` and `updateFilm` and exports it as a Pack; the Theme picker has no agent button.

Skins have the same few properties under the same names, in the Skin panel for the selected pieces or, in Film, the selected marble: **Color** (Skin, Marble, By Note; By Note only on platforms), **On Hit** (None, Press, Wobble, Glow; pieces with no moving part have None and Glow, marbles none at all), **Glow Color** (with Glow, or on a skin that glows), **Variant** (where a skin has variants: a Device's trim; Glass's Swirl or Cat's-Eye) and any extra property an agent-made skin's manifest declares (Ribbon Color). Each row's first choice is the default ("Marble · Default"), a mixed selection shows only what its skins share, and each change is one undo step. The skin picker's first tile, **Theme: Gold Plate**, takes a selection back to its theme's skin and properties. A skin never changes a hitbox, and a marble's skin never changes how it falls.

The theme is a preset of parts: a skin and property defaults per element type. A piece without a skin of its own wears its theme's, with the theme's property defaults; a skin chosen for it keeps its own defaults until its own Color says otherwise (the skin's notice adds "It keeps Copper's color with Color by Note"). Selecting a piece shows what it wears; the inspector lists no parts.

A deep marble is only as dark as that needs, in the band's hue, so a warm wall never gets a near-black ball; the Wall skin **Plain** turns a theme's pattern off. Marbles stay at least 3:1 apart from their wall and their own pieces in every theme: pearl white with the band's hue on the rim on a dark wall (Neon), the band's hue made deep on a light one (Pegboard, Brass), whichever contrasts more; that is the theme's default marble, and Pearl and Deep pick the tone yourself. A Wall color can switch the tone.

Film owns lighting, the wall, titles, effects, decorations and the camera.

### Library

Skins and Decor are Blender assets. Each item is a `.blend` with packed textures and a small manifest with its role, compatible piece type, fitted parameters, contact surface, reaction parts and thumbnail. The app reads manifests without starting Blender. The library folder is registered as a Blender asset library, so it also appears in Blender's Asset Browser.

- The Starter Pack, always present, brings the themes Pegboard, Brass and Neon with skins for every piece type. Pegboard is Compose's look, for users who want that style in the film. Insert lists Decor and the skin and Theme pickers list the rest, with no separate Library panel
- A project copies the items it uses into its own assets, so it stays portable
- There is no global library: to use a look in another project, **Export This Look…** writes it as a Pack, always with the look as a theme, and **Import from File…** in **Packs…** adds it there
- The film's theme is project data (`film.theme`), not a library file, so it travels with the project
- The Starter Pack's skins are not library files: the Blender worker builds them, and their previews are rendered by `blender/tests/render_skin_previews.py` into `public/skins/`
- An item an agent adds with `add_asset` records `origin: "agent"` (Made by Agent); items without it read Imported
- Applying a skin to a piece type also applies it to pieces placed later

### Agents

There is no chat in the window. The person chats in their own Claude Code, Codex or Claude app, which works in the open project through MCP, the same commands a person uses. Edits show live, each one named Undo step ("Agent: Place Platform"), in Edit › Undo and its notice.

**The Agent button** in the title bar opens a small menu: who is connected ("Claude Code connected", "No agent connected", "MCP is off"), Connect Claude Code, Connect ChatGPT and Codex, Copy Command for Other Apps, Enable MCP and Show Agent Folder. While an agent works its glyph pulses and the word Working opens.

**While a call runs**, the notice at the bottom of the canvas in Compose and Film says what it is doing ("Agent · Placing Platform 12") with **Stop**. Calls that only read don't show it, and it goes 1.5 s after the last call. Stop ends a running Build Entire Track, Fix or export, turns away calls waiting behind it, and tells the agent in its reply; what's done stays. A Blender frame already rendering finishes, so the notice reads Stopping until then.

**What an edit changed flashes:** an accent outline like the selection's on the piece, and on its row in Layers for any layer (Wall, lights, Camera, Decor, titles), fading in about a second. With Reduce Motion it shows for that second without a fade.

**"This" is the selection.** The person selects a hit or piece and says "this" in their app; `get_state.selection` resolves it for the agent, including the platform of a hit and the hit of a piece.

**Made items:** what an agent adds with `add_asset` shows in Insert and the skin picker with the origin line Made by Agent, and works like any item. References stay in `agent/references`; an agent stores them with `set_references`, and the window has no panel for them.

### Reactions

A reaction animates part of a skin from the hit value, such as a key pressing down, a bell wobbling or a light flashing. Reactions are visual and never change the physics. Keep presses small so a resting marble does not appear to float.

### Wall text and decals

Clicking the wall places a native Blender text object with font, size and material. Flat prints use decals projected onto the wall. Agents can restyle either.

A title shows for the whole film unless it has In and Out times. The title inspector's Timing panel edits them as `m:ss.cc`, `m:ss` or seconds, like the LCD; a time at the start or the end of the film clears it, and an Out before In is refused. Blender hides the title outside its range and fades it in over 0.25 s after In and out over the 0.25 s before Out (an object property drives a transparent mix in its material, and the title is hidden from renders and the ID pass while it is out). In Film the timeline shows the Titles layer's row after Camera with each title as a clip from In to Out: click selects the title, dragging the clip moves both times, dragging an edge trims one, each as one undo step.

Placing a title selects it and focuses its Text field with the text selected, like Figma's text tool, so typing replaces "Title" at once. A new title takes the color that reads on the wall the project shows: navy on a light wall, white on a dark one; a title with no color of its own (the Color field reads Default) reads in the same rule and follows the wall and a letter height of 6 % of the film frame at the wall, so it reads on a phone. The Title inspector's Style picks one of four:

- **Wall Title**, the default: text on the wall where it was placed, lit like the pieces
- **Caption**: big text near the top of the frame (its center 15 % below the top edge), 6 % of the frame height, for 3 s from the playhead
- **Song Name**: upright text in the upper third of the frame (its center 35 % below the top edge) over the first 3 s of the film, 7 % of the frame height, reading the song's name while the text is still "Title". Added with the playhead outside a title's In and Out, the playhead moves to its In so it shows
- **End Card**: centered text over the last 3 s of the film, 8 % of the frame height

Caption, Song Name and End Card are screen titles, like the overlay titles of the reference films. The exported film draws them onto the frames when it is encoded, centered, with a 0.25 s fade and a bold system font, as plain text, or with a soft dark box and shadow when the title's Plate asks for it, so depth of field can never blur them. Blender's previews and its own encoder, used only without FFmpeg, show 3D copies parented to the film camera by the wall's nearest point, glowing in their color; drivers on the camera's lens, focus and distance keep their place and size in the frame while the camera moves. Their Size is a share of the frame height in %, shrunk when the text would not fit the frame width, and they have no Position. The Draft Preview draws them at the same place and size, in the same font, with the same Plate. Like a title preset in Final Cut or CapCut, choosing a style sets its times while the title still has the previous style's own times or shows for the whole film; times set by hand stay. A caption's own times are any 3 s span.

### Decor

Decor dresses the film and never collides: the simulation doesn't read it, so it can't change a hit. It is Film only: a **Decor** group in Layers after Titles, shown once it holds something like Titles (Lights always holds its Key Light); what you add comes from Insert, one layer per item, with Hide, Rename, Delete, Duplicate (⌘D) and ⌘Z. The inspector has Position, Scale, Rotation, In and Out with a title's pattern and no skin. A selected item drags on the viewer, as one undo step.

**Particles** belong to the frame, not the wall, because the film camera turns as it follows the run: something fixed on the wall would cross the frame. Particles drift in front of everything and always fill the frame, slightly soft; its inspector has Density, Size, Speed and Color, default a soft white-gold. They have In and Out and Hidden like other Decor, and no Position, no drag on the viewer, no Overlaps tip, and Scatter leaves them out. The same layer falls the same way in every render. Flat Light leaves them out. The Draft Preview draws a stand-in on a canvas; with Reduce Motion the snow holds still.

Softness, Exposure and Bloom are a theme's values and Blender's (Color Management, Sun Angle, the compositor's Glare), not panel rows: a theme sets them and an agent can change them.

Film's **Insert** has one Decor section, whose ? says what Decor is: **Sphere**, **Ring**, **Cube** and **Particles** from the **Starter Pack**, plain items for any look, with their origin line, then what added Packs bring and the whole Pack of any item the project has. Several Decor items selected show "3 Decor Items" in the inspector, not the Scene; ⌫, ⌘D and the menus act on them all. A click adds an item at the playhead, a drag places it. Built-in items such as the Christmas Pack's are made procedurally in Blender with a Draft Preview stand-in.

**Path awareness.** An item a marble's path crosses while it shows carries the amber "Overlaps Melody's path" in its inspector and a badge in Layers. It comes through the problem model as a tip, so it counts with the tips of the export sheet and never with the problems of the note summary. **Move Clear** moves it the shortest way to a spot clear of every marble's whole run and of the pieces.

**Scatter Decor…** (the Decor layer's inspector and menu, ⌘K) asks what to scatter, starting from the last choice, and places nothing until **Scatter**; after that each change re-scatters in place, as one undo step, and it replaces only what it placed. It fills the free wall the film camera shows, clear of every path and in the frame's side bands: the middle, 28 to 72 % of the frame's width when the run passes, stays clear for the marble and its pieces. A theme brings no Decor; the panel offers the Starter Pack's Sphere, Ring and Cube, what added Packs bring and the items of the project's own, and it starts only from a last choice it still lists. With nothing to offer it shows **Packs…**. What it places stays folded in Layers, even in a Decor group that was open. Density and **Scatter Again** sit in the same panel.

**Made in Blender.** Anything added directly in the Blender file is Decor too: lights and cameras stay out, and a group counts as its top object. The app lists it in the group when it next talks to Blender, with "Made in Blender" as its origin. It hides, shows and takes In and Out, as keyframes on the object's own visibility; Open in Blender selects it there. Its bounds drive the same tip, without Move Clear, since the app never moves or deletes it. The Draft Preview draws a faint dashed outline, and the inspector says "Shows in the Blender preview".

**The agent.** A request for several items ("Christmas decor along the sides") goes to the person's own agent, which adds them with `add_asset` or a Pack and scatters them, as Undo steps.

### Camera

The default camera is a native Blender camera with baked keyframes:

- It follows the smoothed trajectory at a distance from the wall, turned to the side, so bars fan out from a point just beside the frame. New projects stand it 48 cm from the marble through a 30 mm lens at a 0.54 rad tilt (`references.md`)
- Its target leads the marble, and it barely rolls
- Shot markers on the timeline, such as wide, push in or close on a hit, with eased transitions. A shot's distance is relative to the rig's: it scales whatever the automatic camera frames at that time, so a shot at 0.7 times the rig distance comes 30 % closer also where two marbles have widened the frame, and a close shot frames the leading marble alone. A shot holds for its Hold and then eases back to the automatic camera; a new shot holds 2 s, and a Hold of 0 keeps it until the next one
- After the run's last struck hit the camera stops following: it settles over a second on the last stretch of the run, so the film ends on the final pieces instead of a marble falling down an empty wall. The marble that struck last falls out of this held frame about a second after its hit; a film whose end is later than that holds on the pieces alone. The default song length, the last note plus 0.4 s, ends on the marble. With Bowls, the held frame sits half way between the last hit and the mouths of the Bowls that catch a marble after it, so the film ends on the last piece and the marble landing in its Bowl, 1.2 s after the last note

- It stays steady and every marble that plays stays in frame: a group always fits, sized as the camera sees it, with its pitch and roll, and its zoom changes slowly. A marble counts only until 0.6 s after its last note while another marble still plays: then the camera keeps the marbles that play on and lets the finished one fall away. In a Push In or Close-Up it frames the leading marble alone, the one with the most notes in the next 2 s; the focus marble, the first or `design.camera.focusMarbleId`, wins a tie. The opening stands at most 1.5 times the rig distance
- The wall is generated on every apply to cover the run and everything the camera sees, so the film never shows its edge. A wall edited in Blender is left alone

The Camera layer's inspector (select Camera in Layers or its row in the timeline) exposes **Follow Marbles**, on by default, Distance, **Turn**, Tilt and **Sway**; shots are its markers. Off, the camera is yours: it stays where it is, and the panel says in a line to move it in Blender, with **Open in Blender**. Turn is how far around the marbles the camera stands, 95° unless set. With the Camera selected in Film, dragging in the preview orbits it, like Blender's Lock Camera to View: left and right change Turn, up and down change Tilt, one Undo step per drag. The Draft Preview answers at once, and Blender's picture catches up when the drag stops. Sway is how much the view turns and rolls on its own: 100 % as it always did, 0 % holds the Turn and keeps the wall upright, so what stands upright on it stays upright. Look Ahead and Smoothing stay project values for agents, without a row. The focus marble has no control yet. Add Shot (⇧M or Insert) places a marker at the playhead at 0.7 times the rig distance; double-clicking the Camera row adds one at that time. Clicking a marker selects it and the inspector shows its Preset, Time, Distance and Hold. The Camera row draws each shot's span behind its marker: to its hold's end, where a fade shows the ease back, or to the next shot. A Preset only sets the distance relative to the rig (Wide 1.6×, Normal 1×, Push In 0.7×, Close-Up 0.45×), which the user can then fine-tune; any other distance reads Custom. Dragging a marker moves its time in one undo step, and Delete removes it. Markers stay sorted by time. Editing the camera in Blender takes it over ("Edited in Blender"), and Reset Camera gives it back.

### Preview and render

The Film preview is a low-resolution Eevee render of the current playhead from the real scene. Over Blender's frames, as over the Draft Preview, the selection stays marked: its outlines are drawn through the same camera in their own layer above the frame. Whenever that render is not there (the browser, Blender not installed, starting or failed) the **Draft Preview** stands in, like Final Cut's proxy playback: the app draws the run through the same follow camera (the TypeScript port, with shots; a manual camera falls back to the automatic one) with the Compose renderer's Camera view, and approximates the theme's look in flat colors: Pegboard's hardboard with peg holes and toy colors, Brass's lavender plaster with gold, copper, silver and dark bars, chrome rails and devices, the Color by Note wheel of the Blender theme, and titles as text at their wall positions with their timing fades. Clicks pick pieces and titles (Shift adds), the Title tool places a title where the wall is clicked and returns to Move like Figma's Text tool (⇧-click keeps it for another title), Neon's Draft Preview adds a soft halo around its glowing pieces, pearl marbles get a ring in their label color's hue and deep ones their dark label color, Brass skins draw their shape cue (chrome end caps on a bar, a Device's trim-colored ends and grille, a Key's white key, a Knob's red lens), the frame letterboxes to keep the film's aspect in a narrow pane, screen titles draw at the size the encoder burns in, library drops skin the piece under the pointer, and scrubbing and playback move it. When Blender's render is ready it replaces the draft. Film shows the real look by default: while Film is open and the person isn't working, Blender renders small frames with the film's own lights in the background, like Final Cut's background render: around and ahead of the playhead first, then outward over the whole song. Pressing, dragging, typing, scrubbing, an edit or playback pauses it, on low priority and about one core when it runs, and it goes on from the playhead 1.5 s after they stop. Playback and scrubbing show these frames where they exist and fade to the Draft Preview where none is rendered yet; a paused playhead shows Blender's still once it is ready. The separator line under the Film ruler is the render bar: it fills green over the rendered spans (tooltip "Rendered in Blender") and keeps its neutral color elsewhere, with the tooltip "Rendering in Blender…" while it renders; the Blender button reads Rendering Preview meanwhile. Any change to the film starts again from the playhead; undo brings back frames already rendered. **View › Draft Preview** (and ⌘K) shows only the draft and stops the background render to save energy. Placing a title maps the click through the film camera's pose in both previews. The final render runs in Blender in the background with progress shown in the app.

The timeline is the film, as in a video editor: 0 is its first frame, which holds the marble and the first pieces. To start later, move the song later; a recording's long intro goes by dragging its clip past 0. Export offers two qualities: Draft (720p, 30 fps), for testing and to check motion in under a minute, and Final (1080p, 30 fps, Eevee) for the film. Other renderers and sizes are Blender's: Open in Blender. Draft is for judging placement, motion, timing and the camera quickly: it renders the same scene, camera, frame range and soundtrack with Blender's Workbench instead of Eevee, in solid theme colors close to what Fast shows (Flat Light: flat lighting through the theme's view transform and look, so the wall keeps the same color at any camera angle and playback does not flicker between Flat Light and Fast frames) with short shadows, cavity and outlines and without materials, depth of field or motion blur. Its picker entry reads "Draft · 720p · Flat Light", against "Final · 1080p", and the sheet remembers the last choice per project. Export Film… (⌘E) opens a sheet with the quality, the file name and an estimated time: the frame count times the per-frame time of the last film rendered at that quality, or of the playhead preview scaled to the film size; Draft without a film of its own uses the typical Workbench time. Above the buttons a preflight checks the current simulation result, like Final Cut's share warnings with Xcode's issue list: a summary line ("115 of 115 notes on time" with a check, or "3 issues · 1 tip") discloses the issues, warnings first. Problems are what the note summary lists, which are physics: missed, blocked, early and late hits with their reason, stray contacts, touching, double bounces, rolls and a marble passing through something; and in Film a marble out of frame for 1.5 s or more while it plays, and a screen title wider than the frame. Tips are open notes, shorter stays out of frame, Decor over a path, a long fall and the first frame's measurable facts, in one tip that names only what falls short: the melody under 6 % of the frame's width, or out of it, round Decor close enough to pass for it, fewer than 6 pieces in frame unless the song strikes fewer in its first 3 s, or a marble, the first piece or a wall title in the bottom fifth, where YouTube's buttons sit. Beside the summary the sheet shows that first frame, rendered by Blender. A result for an older revision shows "Checking the track…". Clicking an issue closes the sheet, switches to Compose, moves the playhead to it and selects and frames the hit or piece. Issues never block the export; the default button then reads Export Anyway. While rendering the sheet shows the frame, elapsed and remaining time and Cancel; it can be hidden while the title bar's Export Film… button keeps the progress as a ring. A finished film plays in the sheet with Show in Finder. By default the marble whose notes sit highest, by their median pitch, is the melody: the other marbles and Backing play 10 dB under it and lose what's under 150 Hz, in the preview and in the film, as phones reproduce little down there and marble notes blur together. A Level chosen on a marble or on Backing wins, with nothing cut. Mute and Solo don't change who the melody is, and a recording plays as it is. Every film's sound is brought to −14 LUFS with its true peak at −1 dB, the same for Draft and Final: one gain over everything, so the song's balance stays, and a limiter on the few attacks that gain lifts past the peak. The sheet's summary names the figure, and the finished film names what it reached; the preview stays at the song's own level. Films are rendered into the package's `renders/` folder and then copied to the location chosen in the save panel.

## Connecting an agent

**Enable MCP**, in the Agent menu as well as the Help menu, is on by default. **Connect Claude Code** and **Connect ChatGPT and Codex** run that app's own command in the background, replacing any entry for an older path, and turn on Enable MCP; the notice says to start a new session there. A row reads **Disconnect …** while that app lists this copy of MidiMarble, checked each time the menu opens; Disconnect leaves Enable MCP on. If the app can't be found the row stays, and a click copies the command to paste into Terminal or hand to an agent. **Copy Command for Other Apps** copies the command any other app runs as a local stdio MCP server. While the app is open, an agent reads the project, runs any command of the palette, places pieces with parameters, adds a song, references and assets, looks at frames and exports. Every edit shows live as one Undo step named like "Agent: Place Platform", in a notice with Undo and in Edit > Undo. If the person is mid-drag or an alert is open, the agent waits briefly or is told to try again.

**References** are images and words for the film's look. They live in `agent/references` and `get_state`, stored with `set_references`, with no panel in the window. **Show Agent Folder** in the Agent menu opens the project's `agent/` folder in Finder.

## Packs

Everything comes from a Pack. The **Starter Pack** is always present and can't be removed: the themes, the skins, the wall skins, Sphere, Ring, Cube and Particles, as manifest entries (`packs/Starter.marblepack`) pointing at what the app draws itself. **Packs…** (Insert's foot in Film, Scatter Decor while it has nothing to pick, ⌘K, File menu), like Figma's Libraries, is the one place: a sheet of Pack cards, Starter first and shown as Added, then bundled ones such as **Christmas** (baubles, a snowflake, a fairy light, a gift box and a star), each with a detail view and Add or Remove, and **Import from File…**. Adding changes nothing visible: items appear in Insert and the skin tiles with their origin ("Christmas Pack"), themes in the Theme picker. Using one copies it into the project. **Remove Pack** in a Pack item's menu or the sheet takes it off this Mac; projects keep what they use. **Export This Look…** in the same sheet makes a Pack from the current look, always, and chosen skins and decor, with a name and optional author and link. An item from a Pack not on this Mac still renders and reads "Christmas Pack · Not Added"; clicking the line opens the Pack's card.

## Ownership

| App owns                                          | Blender owns                         |
| ------------------------------------------------- | ------------------------------------ |
| Piece holders, transforms and motion              | Skins, materials and textures        |
| Marble and windmill keyframes                     | Lights, world, particles and effects |
| Hit values, timing, frame rate and audio          | Decorations and compositing          |
| The generated camera rig until the user takes over | The camera after the user takes over |

App-owned objects live in a managed collection with locked transforms. Every app-owned object has a link state, similar to Figma components:

- **Linked**: the app drives it (nothing to show)
- **Detached**: Blender owns it; the app shows it as Detached and stops changing it

Discard Blender Changes gives a Detached object back to the app.

Blender changes never sync back automatically. Physics changes timing, which only Compose can show.

## Project file

A project is a `.marble` package, a folder shown as one file on macOS. Moving the package moves the whole project to another computer, so every path inside it is project-relative. It contains the project JSON, `scene.blend` and assets. The `.blend` embeds a copy of the project JSON so the scene keeps its context when opened alone. The JSON stays outside the `.blend` so the app opens projects and shows the library without starting Blender.

## Findability

Film's **Layers** keep their order and open with the marbles and Decor closed, so the Camera, the Wall and the Lights show without scrolling; a selection made on the wall opens its group. **⌘K** finds layers and settings by name and everyday word, and "solo" leads to the Song, which has Mute and Solo on its row, as a marble with notes has on its own. **Format** (the film's shape) is in Film's Scene. The Camera has Follow Marbles, Distance, **Turn**, **Tilt** and Sway. The preview has a **Draft** or **Blender** switch on it. Decor has no Item choice: swapping is delete and insert. Film's Insert lists Decor, Titles and Lights, with Packs… at its foot; a shot is added on the Camera's row or with ⇧M, a marble and the song in Track. The menu bar's **Insert** menu lists both tabs' additions and opens the right tab.

## Color and notices

**A marble has one color; on other layers a color is a label.** Clicking a layer's icon or dot, which lights up on hover with the tooltip Color, on Layers rows and timeline rows, opens the system color picker, with the marbles' colors offered first; Clear Label Color in its menu takes a piece's, a title's or Decor's away. It organizes the project, like Blender's collection color tags and Logic's track colors: the icon, dot, timeline row, hit marks and the trajectory wear it, and in Track, 2D and 3D, so do the marble and the piece. A piece with no color of its own wears its marble's, or plain Pegboard wood with no marble. A marble's color is also its color in the film: a skin with Color Marble shows it on the marble and on the pieces it plays, and a skin with Color Skin keeps its own, as Gold and a clear marble do. On every other layer a label shows in Film only on the skin None.

**Notices** sit at the bottom center of the canvas, above the transport and above the bar when it shows, in both workspaces. First-run hints wait while a notice shows. **MIDI import** names marbles from the file's track names (Melody, Bass) in the sheet and the project; a track without a name, or one two marbles would share, keeps Marble 1.
